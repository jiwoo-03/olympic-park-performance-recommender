## 사전 작업: API 엔드포인트 특정

`APIKEY.md`에 있던 4개 서비스키는 워크플로우 문서의 설명과 달리 **정확한 호출
엔드포인트가 공개 문서에 명시되어 있지 않았다** (data.go.kr 상세 페이지는 "연계(LINK)"
형 API라 요청 URL을 직접 보여주지 않음). data.go.kr의 DCAT 메타데이터(`/biz/dcat/metadata/{id}.do`)에서
`accessURL`을 추출해 실제 제공기관(문화공공데이터광장 api.kcisa.kr, 또는 KSPO 자체 CSV
다운로드)을 역추적했다:

| data.go.kr 데이터셋 | 식별자 | 실제 엔드포인트 |
| --- | --- | --- |
| 공연 정보(통합) | 15056881 | `https://api.kcisa.kr/openapi/API_CCA_144/request` |
| 올림픽공원 대관정보 | 15015212 | `https://api.kcisa.kr/openapi/service/rest/meta12/getKSCD0803` |
| 차량 입출차·날씨 | 15164822 | `https://api.kcisa.kr/openapi/API_CPM_009/request` |
| 영문 공연정보 | 15149169 | 파일데이터 — `data.go.kr`가 자체 호스팅 (서비스키 불필요) |

KOPIS는 이미 공개된 `http://www.kopis.or.kr/openApi/restful/*` 엔드포인트를 그대로 썼다.

## 소스별 상세

### 1. KOPIS 공연예술통합전산망

- 올림픽공원은 KOPIS 시설그룹코드 `FC001247` (`/openApi/restful/prfplc?shprfnmfct=올림픽공원`로 확인,
  하위 공연장 12개: KSPO DOME, 우리금융아트홀, 핸드볼경기장, 88잔디마당, 수변무대 등).
- 목록은 `/openApi/restful/pblprfr?prfplccd=FC001247`로 2013-01-01 ~ (오늘+1년)을 조회했다.
  **1회 호출 최대 100건**이라 페이지네이션 필수(`rows=1000`은 오류 `06 최대 조회수는 100건까지 가능합니다`).
- 목록 821건 중 상세(`/openApi/restful/pblprfr/{mt20id}`) 수집 성공 812건, 9건은 `400 Bad Request` —
  KOPIS 쪽에서 비공개 처리되었거나 삭제된 공연으로 추정(`performance_detail_failed.json`에 id 기록).
- 상세에는 장르, 출연진(prfcast), 공연시간, 관람연령, 요금 안내, 포스터, 예매처 링크(relates)가 모두 들어있어
  추천 모델의 콘텐츠 특성으로 바로 쓸 수 있다.
- 상세에는 인기도(예매상황판)에 해당하는 필드가 없다 — `visit`은 내한공연 여부(Y/N)일 뿐이다.
  대신 KOPIS의 별도 박스오피스 API `/openApi/restful/boxoffice`(`collect_kopis_boxoffice.py`)가
  전국 예매 랭킹 상위 50건을 돌려주며, 응답의 `mt20id`가 상세 수집의 `mt20id`와 동일한 키라
  추가 매칭 없이 조인 가능하다. 기간은 **최대 31일**까지만 조회 가능(초과 시 오류
  `05 최대 31일까지 조회가능합니다`)해서 월 단위로 순회 호출한다. 테스트 호출(2025년 1월) 결과
  전국 상위 50건 중 17건이 올림픽공원 공연(주로 KSPO DOME 대형 콘서트)이었다 — 소규모 공연은
  랭킹에 안 잡히지만, 대형 공연 위주인 올림픽공원 특성상 커버리지가 기대보다 좋다.
- 실제 실행 결과(최근 12개월 월별 수집): 600건(중복 포함) 중 distinct 공연 424건, 그중
  올림픽공원 공연(KOPIS 매칭 812건 기준)과 겹치는 건 **84건** — 전체 매칭 공연의 약 13%가
  인기도 신호를 갖게 된다. 나머지는 전국 상위 50위 밖이라 신호가 없고, 전처리 단계에서
  중립값(또는 0)으로 둔다.

### 2. 문체부 공연 정보(통합) API

- 이 API는 10개 기관 데이터가 한 목록에 섞여 있고 **기관으로 거르는 서버 파라미터가 없다** —
  `numOfRows=1000`으로 전체 58,935건을 59페이지에 걸쳐 모두 순회한 뒤, 응답의 `CNTC_INSTT_NM`에
  "한국체육산업개발"이 포함된 행만 걸러 저장했다 (2,780건). 원본 그대로를 보존한다는 원칙과 수집
  단계에서 꼭 필요한 데이터만 남긴다는 실용성 사이에서, "KSPO분만 저장"을 수집 단계의 설계로
  명시했다.
- KSPO가 제공하는 행에는 `GENRE`, `EVENT_SITE` 칼럼이 거의 항상 비어 있다 — 워크플로우 문서가
  우려한 대로 **"KSPO 데이터에 장르·설명이 없을 가능성"이 실제로 확인됨**. 대신 장소 정보는
  `SPATIAL_COVERAGE`에 들어있다 (예: `KSPO DOME`, `88잔디마당, 88호수수변무대`).
- **데이터 품질 이슈**: 2,780건 중 819건(29%)은 실제 공연이 아니라 "준비대관", "예약완료",
  "철거대관" 같은 대관 운영 상태 레코드였다. 전처리 단계(`match_performances.py`)에서
  제목 키워드로 제외한다.

### 3. 영문 공연정보 (CSV)

- "파일데이터"라 서비스키 없이도 다운로드 가능. data.go.kr는 다운로드를 2단계로 처리한다
  (`selectFileDataDownload.do`로 최신 `atchFileId` 조회 → `fileDownload.do`로 실제 파일 요청).
  파일은 CP949로 인코딩되어 있어 UTF-8로 변환해 저장했다.
- 286건, 2018~2025년 과거 공연 이력. 장르·설명 없이 행사명/기간/장소/예매링크만 있다.

### 4. 한국체육산업개발 올림픽공원 대관정보 (실패)

- `https://api.kcisa.kr/openapi/service/rest/meta12/getKSCD0803`에 발급받은 서비스키로 호출하면
  **401 Unauthorized**가 반환된다. 파라미터(`serviceKey`/`numOfRows`/`pageNo`)는 공식 명세와
  동일하게 맞췄고, `Authorization` 헤더 방식도 시도했으나 동일하게 실패했다.
- 이 API는 2016년에 등록된 구세대 게이트웨이(`meta12`)이고, 정상 동작한 `API_CCA_144`/`API_CPM_009`는
  더 최근 체계다. 활용신청이 자동승인이라고 안내되어 있지만 **레거시 게이트웨이 쪽 키 반영이
  지연되었거나 별도 승인이 필요한 것으로 추정**된다.
- 영향은 제한적이다 — 같은 대관 정보(행사명·기간·장소)를 문체부 통합 공연정보 API에서
  "한국체육산업개발" 기관 필터로 이미 확보했기 때문에, 전처리 단계는 이 API 없이도 진행했다.
- **확인할 것**: data.go.kr 마이페이지에서 15015212 활용신청 상태를 확인하고, 필요하면 재승인
  요청. 승인되면 `collect_kspo_venue_rental.py`는 수정 없이 바로 동작한다.
- **2026-11-12 재확인**: 사용자가 `APIKEY.md`에서 새 키를 찾아와서 `serviceKey` 쿼리 파라미터로
  재시도 → **401은 해결됨**(`resultCode: 0000`, 717건). 하지만 날짜가 들어갈 `temporalCoverage`
  필드가 100건 샘플 전부 빈 값이고, `regDate`도 보도자료 API 때처럼 "수집 시각"일 뿐 행사
  날짜가 아님 — 제목에 "2013 뮤즈 인시티 페스티벌" 같은 오래된 행사가 섞여 있는 걸 보면
  날짜 없이 쌓인 과거 대관 이력 아카이브로 보인다. **날짜 정보가 없어서 공연 일정 UI로는
  못 쓴다** — 이미 문체부 통합 공연정보 API+KOPIS 매칭으로 확보한 기존 데이터(실제 기간
  포함)가 이것보다 낫다. 수집 스크립트(`collect_kspo_venue_rental.py`)는 그대로 안 씀.

### 5. 차량 입출차·날씨 정보 (실패)

- `https://api.kcisa.kr/openapi/API_CPM_009/request` 호출 시 **504 Gateway Timeout**이 재시도
  3회 모두에서 발생했다. 401(인증 실패)이 아니라 504(게이트웨이 타임아웃)이므로 키 자체는
  유효해 보이고, 제공기관(KSPO) 쪽 백엔드 서버 장애 또는 과부하로 추정된다.
- **2026-11-12 재확인**: 사용자가 `APIKEY.md`에서 새 키로 같은 `API_CPM_009`와, 차량 입출차만
  단독 제공하는 `API_CPM_008`(올림픽공원 차량 입출차 정보)을 추가로 찾아와서 둘 다 재시도함.
  - `API_CPM_009`(새 키): 504 Gateway Timeout — 전과 동일.
  - `API_CPM_008`(새 게이트웨이): 연속 호출 시 429(요청 제한, 10초당 1건)까지는 정상
    응답했지만, 간격을 두고 단독 호출하면 60초 넘게 기다린 끝에 역시 **504 Gateway
    Timeout**. 게이트웨이 엣지(rate limit)는 살아있지만 뒷단 데이터 서버가 응답을 못
    주는 것으로 확인 — `API_CPM_009`와 같은 제공기관 백엔드 장애로 결론.
- **확인할 것**: 며칠 후 재시도. 계속 실패하면 담당부서(한국체육산업개발, 02-2180-3504)에
  문의가 필요하다. 이 데이터 없이는 주차 혼잡 예보 모델(6장)과 "실시간 차량 입출차 UI"를
  만들 수 없으므로, 4주차 이전에 반드시 해결해야 하는 블로커다.

## 재현 방법

```bash
cd pipeline/collection
pip install -r requirements.txt
python run_all.py
```

`.env`에 4개 서비스키가 있어야 한다 (`.env.example` 참고). 결과는 프로젝트 루트의
`data/raw/<source>/` 아래 JSON/CSV로 저장된다.
