# 추천 모델 오프라인 평가 리포트

작성일: 2026-11-12

워크플로우 문서 4.4·6장의 완료 기준("가상 프로필 30개의 장르 일치율 등 오프라인 평가표")에
따라 작성한다. 평가 스크립트는 `evaluate.py`, 원본 결과는 `evaluation_results.csv`.

## 평가 설계

- 가상 프로필 30개 = 실제 장르 6종(콘서트·뮤지컬·클래식·페스티벌·어린이·스포츠/기타, "미분류"는
  선택 가능한 취향이 아니므로 제외) × 5명. 각자 장르 하나만 좋아한다고 가정 — "그 장르를
  좋아하는 사람에게 실제로 그 장르가 추천되는가"를 가장 직접적으로 검증하는 구성이다.
- `taste_recommend()`를 프로필당 1회 호출(top_k=5), 평가 시점은 2026-11-12로 고정.
- Precision@5 = 반환된 5건 중 target_genre와 일치하는 비율.
- Coverage = 30개 프로필 전체에서 한 번이라도 추천된 공연 수 / 평가 시점에 추천 가능한
  (종료되지 않고 "미분류"가 아닌) 전체 후보 수.
- Diversity = 추천 목록 1개 안에 등장한 고유 장르 수(평균).

## 결과

| 지표 | 값 |
| --- | --- |
| 평균 Precision@5 | **0.200** |
| 평균 Diversity(목록 내 장르 수) | 1.83 |
| Coverage | 6 / 13 = 0.462 |

**장르별 Precision@5**

| target_genre | Precision@5 |
| --- | --- |
| 콘서트 | 1.0 |
| 스포츠/기타 | 0.2 |
| 뮤지컬 | 0.0 |
| 클래식 | 0.0 |
| 페스티벌 | 0.0 |
| 어린이 | 0.0 |

## 원인 분석 — 알고리즘 버그가 아니라 데이터 커버리지 문제

Precision@5가 콘서트 말고는 전부 0에 가까운 건 추천 로직이 잘못됐기 때문이 아니다.
**매칭된 공연 651건 중 2026-11-12 기준으로 아직 끝나지 않은 공연이 13건뿐이고, 그중
12건이 콘서트, 1건이 "스포츠/기타"(최현우 마술)다 — 뮤지컬·클래식·페스티벌·어린이는
예정 공연이 0건이다.**

```
매칭 공연 651건 (장르별: 콘서트 542, 페스티벌 33, 뮤지컬 30, 스포츠/기타 19, 클래식 18, 어린이 9)
  → 2026-11-12 기준 종료: 638건
  → 안 끝난 공연: 13건 (콘서트 12 + 스포츠/기타 1, 나머지 장르 0건)
```

즉, 뮤지컬을 좋아하는 가상 사용자에게 추천할 수 있는 뮤지컬 공연이 **데이터에 하나도
없어서**, `taste_recommend`는 (정상 동작으로) 차선책인 콘서트·최현우 공연을 대신 보여준
것이다. 이건 워크플로우 문서 7장이 이미 예상한 리스크 1번("특정 시기 예정 공연이 몇 건뿐임
→ 추천 선택지가 적어 체감 품질 저하")이 실제 데이터에서 그대로 확인된 사례다.

**근본 원인 후보**:
1. KOPIS 수집 시점(2026-11-09)에는 뮤지컬·클래식·페스티벌·어린이 공연도 "오늘+1년"
   범위에 있었을 텐데, 올림픽공원이라는 장소 특성상 그런 장르는 티켓 오픈이 콘서트보다
   늦게(공연일에 더 가까워져서) 이뤄지는 경향이 있어 아직 KOPIS에 등록이 안 됐을 수 있다.
2. 올림픽공원 자체가 대형 콘서트장(KSPO DOME 등) 중심이라, 구조적으로 뮤지컬·클래식
   상연이 드문 공연장일 수 있다(7장 리스크와 동일).

어느 쪽이든 **매일 재수집하면 자연히 나아질 가능성이 있는 문제**(1번)와 **구조적으로
계속 남을 문제**(2번)가 섞여 있어, 지금 시점의 숫자를 "영구적인 실패"로 보기보다는
"현재 시점 스냅샷"으로 해석해야 한다.

## Coverage·Diversity 해석

- Coverage 0.462(6/13): 13건의 후보 중 6건만 30개 프로필 전체에서 한 번이라도 추천됐다.
  후보 자체가 13건뿐이니 당연한 결과 — 모수가 커지면(예정 공연이 늘면) 이 지표가 더
  의미를 가진다.
- Diversity 1.83: 콘서트를 좋아하는 5명은 전부 diversity=1(콘서트만), 나머지 25명은
  diversity=2(콘서트 4개 + 최현우 마술 1개가 보통 섞여 나옴) — MMR이 "같은 장르 몰림
  방지"를 시도는 하지만, 애초에 후보가 2개 장르뿐이라 다양성을 더 끌어올릴 재료가 없다.

## 결론 및 제안

- **코드 버그는 없음** — 추천 로직(2단계)은 설계대로 정확히 동작하고 있다.
- **지금 수준으로 MVP 데모를 한다면** 사용자가 뮤지컬·클래식·페스티벌·어린이 취향을
  고르면 사실상 전부 콘서트가 대신 추천되는 상황을 보게 된다. 공모전 시연 전에 다음 중
  하나는 결정이 필요하다:
  1. `pipeline/collection`을 데모 직전에 재실행해 최신 KOPIS 데이터로 "안 끝난 공연" 폭을
     넓힌다(그래도 올림픽공원 특성상 콘서트 편중은 어느 정도 남을 수 있음).
  2. 조건 추천(`condition_recommend`)의 날짜 범위를 넓히거나, "예정 공연이 적으면 과거
     유사 공연이라도 참고용으로 보여준다"처럼 폴백 로직을 추가한다.
  3. 발표 자료에서 이 한계를 "워크플로우 문서 7장에서 예상한 리스크가 실측으로 확인됨"
     이라고 투명하게 설명하고, 향후 대응 방향(공원 내 무료 행사·전시까지 대상 확대)을
     제시한다.

## 추가 조치 (2026-11-12) — 1번 옵션(재수집) 시도 결과

사용자 요청으로 데이터 재수집 + 매칭 알고리즘 개선(KSPO 제목의 "［얼리버드 50%］"류
프로모션 문구 제거)을 시도했다. 결과: **매칭 1건 복구(백 번째 리뷰, 연극)는 성공했지만
Precision@5는 0.200으로 그대로**, 유의미한 개선은 없었다.

원인: `performances.csv`의 `period`가 KSPO 쪽 기간을 쓰는데, 복구된 "백 번째 리뷰"는
KSPO 기간(2026.08.30 종료)과 KOPIS 기간(2026.12.27 종료, 연장 공연으로 추정)이 달라서
여전히 "종료된 공연"으로 분류돼 추천 후보에서 빠진다. 이건 재수집으로 해결되는 문제가
아니라 **매칭된 공연의 기간을 어느 쪽 소스로 쓸지**(KSPO vs KOPIS)를 정해야 하는 별도
이슈다 — `tasks/todo.md`에 후속 작업으로 남겨둔다.

결론적으로 **2026-11-12 시점에서는 여전히 뮤지컬·클래식·페스티벌·어린이의 예정 공연이
0건**이고, "결론 및 제안"의 3가지 선택지(데모 전 재수집/폴백 로직/투명 공개) 중 재수집은
이미 시도해본 상태 — 남은 선택은 (b) 폴백 로직 추가, 또는 (c) 한계를 투명하게 설명하고
넘어가는 것 중 하나다.

## 설계 전환 (2026-11-12) — 콘텐츠 우선 모드

재수집·매칭 개선으로도 Precision@5가 나아지지 않아서(위 "추가 조치" 참고), 추천 방식을
근본적으로 바꿨다. 사용자와 논의해 다음 방향으로 결정:

1. **반복 시리즈 다음 회차 예측**(`series.py`, 규칙 기반 — ML 모델 아님): 제목(연도 제거)이
   3회 이상 반복된 공연(그랜드민트페스티벌·서울파크뮤직페스티벌·뷰티풀민트라이프·성시경
   관련 2종, 총 6개 시리즈)의 가장 최근 회차를 1년 뒤로 투영해 "다음 회차 예상"으로
   후보에 넣는다.
2. **취향 추천·비슷한 공연은 날짜 확정 여부와 상관없이 콘텐츠(장르+출연진+제목)로 추천**
   하고, 결과마다 상태를 표시한다: `확정 예정` / `매년 반복 예상` / `과거 유사 공연 — 참고용`.
   조건 추천·콜드스타트("이 날짜"/"이번 주말"을 묻는 기능)는 날짜 기반을 그대로 유지한다
   — 특정 날짜를 물었는데 과거 공연을 보여주는 건 거짓 정보이기 때문.
3. **`scoring.CONTENT_FIRST_MODE` 스위치**로 전환 가능하게 구성. 한국체육산업개발이 실제
   서비스로 채택해 미래 공연 일정이 충분히 들어오게 되면, 이 값을 `False`로 바꾸는 것만으로
   원래 설계(확정된 예정 공연만 추천)로 되돌아간다 — 코드 재작성 불필요.

**재평가 결과**: Precision@5 **0.200 → 0.800**(뮤지컬·어린이·페스티벌 1.0, 클래식 0.8,
콘서트 1.0). 스포츠/기타만 0.0인데, 이 장르는 애초에 "서커스/마술·연극·무용을 뭉친
잡동사니 버킷"이라 장르 신호를 안 주기로 결정했었어서(위 "스포츠/기타 장르 가짜 군집"
참고) 당연한 결과다. Coverage는 분모가 13→719로 커져서 숫자 자체(0.033)는 낮아 보이지만,
이건 "과거 공연까지 전부 후보가 됐다"는 의미라 이전과 같은 기준으로 비교할 수 없다 —
다음에 이 지표를 볼 때는 "최근 N개월 내 추천된 적 있는 공연 비율"처럼 재정의가 필요하다.

**남겨둔 한계**: 반복 시리즈 예측 5건은 이번 평가에서 top5에 하나도 안 들었다(예측 공연은
인기도 신호가 0이고 날짜도 보통 30일 근접도 범위 밖이라, 실제 확정/과거 후보에 밀림).
기능은 정상이지만 지금 당장 체감 효과는 적다 — 예측 날짜가 가까워지면 자연히 반영될 것으로
기대.

## 버그 수정 (2026-11-12) — 장르 선택 간 결과 중복

사용자가 "장르를 다르게 선택해도 똑같은 공연이 나오는 오류는 없었냐"고 확인을 요청해서
6개 장르를 직접 대조해본 결과, **"스포츠/기타"를 선택하면 "콘서트"와 완전히 동일한 5건이
나오는 버그**를 발견했다. 원인: "스포츠/기타"는 장르 벡터 쪽에서 신호를 0으로 죽여놨는데
(위 "스포츠/기타 장르 가짜 군집" 참고), 사용자 프로필을 만드는 `build_profile_vector`는
그걸 모르고 여전히 그 장르에 1을 넣고 있어서, 모든 공연과의 유사도가 똑같이 0이 돼
인기도 순위(=콘서트 랭킹과 동일)로 조용히 대체되고 있었다.

수정 후: "스포츠/기타"만 선택하면 프로필이 완전한 영벡터가 되어 기존 콜드스타트
폴백("취향 정보 없음")이 정상적으로 발동한다. 재평가 결과 전체 Precision@5는 0.800으로
동일(스포츠/기타는 버그 전후 모두 0.0이었지만, 이제는 "거짓으로 콘서트를 베낀 값"이
아니라 "실제로 콜드스타트 2건만 반환"이라는 투명한 결과다). 나머지 5개 장르는 서로 완전히
다른 고유 리스트를 반환함을 확인했다.

## 후속 이슈 해결 (2026-11-12) — 매칭 공연 기간을 KOPIS 우선으로

위에서 미해결로 남겼던 "매칭된 공연의 period를 KSPO/KOPIS 중 어느 쪽으로 쓸지" 결정을
실제로 비교해서 해결했다. 매칭 646건 전체를 비교한 결과, 날짜가 다른 23건(3.6%) 전부
종료일은 KOPIS가 KSPO보다 짧은 적이 없어서 "KOPIS 우선"과 "둘 중 늦은 종료일"이 실질적
으로 같은 결과 — 더 단순한 "매칭된 공연은 KOPIS 기간을 쓴다"로 정했다
(`normalize_and_clean.resolve_period()`).

결과: "백 번째 리뷰"가 `확정 예정`으로 정상화되고, 오프라인 평가 Precision@5가
0.800 → **0.855**로 올랐다(스포츠/기타 0.0→0.333).
